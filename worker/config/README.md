# Настройки агента на хосте

Секреты здесь не лежат. Их держат в `/etc/ai-family.env` на машине воркера: ключ Cursor, GitHub, Telegram, Supabase и закрытый бакет Hetzner для фотографий и входящих вложений.

Повторить на новом хосте:

1. Запустить `scripts/setup-worker.sh` от root. Он ставит Node.js 22 и Cursor CLI.
2. Положить `/etc/ai-family.env` и запустить `scripts/install-agent-config.sh` от root. Скрипт копирует `mcp.json` в `/root/.cursor/mcp.json` и вливает `cli-permissions.json` в `/root/.cursor/cli-config.json`.
3. Склонировать этот репозиторий в `/opt/ai-family` и включить `worker/ai-family-worker.service`.
4. Пуш в `main` деплоит сам: GitHub Actions заходит по отдельному SSH-ключу и запускает `scripts/deploy.sh`. Ключ на сервере ограничен этой командой. Приватная половина лежит в секретах репозитория `DEPLOY_SSH_KEY`, `DEPLOY_HOST`, `DEPLOY_KNOWN_HOSTS`.

`cli-permissions.json` разрешает веб-поиск, чтение страниц, `git`, файлы рабочей папки и MCP GitHub. Чтение `.env` и `rm` запрещены.

Сессии диалогов — каталог `/var/lib/ai-family/chats/` на хосте. Личный чат — файл `user:<id>`, тема группы — `topic:<chat>:<тема>`. В файле id чата Cursor, `startedAt` и `updatedAt`. Это состояние машины, в git его нет. Воркер создаёт отдельную рабочую копию проекта для каждого контекста в `/var/lib/ai-family/repos/contexts/` и обновляет её перед заданием. Личные диалоги используют `/var/lib/ai-family/workspace/contexts/`. Входящие вложения и геометки сохраняются в Hetzner Object Storage при запуске задачи; ключи объектов остаются в `agent_jobs.artifacts`. Перед запуском агента файлы копируются в `inbox/` своей копии. Обычный Telegram Bot API разрешает скачивать файлы не больше 20 МБ; для больших файлов в записи остаётся причина недоступности. По умолчанию одновременно выполняется не больше трёх задач; лимит задаёт `MAX_CONCURRENT_AGENTS` в `/etc/ai-family.env`. Витрину выкладывает не этот репозиторий, а пуш в `main` репозитория проекта.

Запуск агента ограничен 10 минутами (`AGENT_TIMEOUT_MS` в миллисекундах). Если время вышло, воркер останавливает процесс и повторяет задачу в прежнем контексте до трёх попыток, удерживая порядок сообщений в этой ветке. Скрипт выкладки устанавливает зависимости до перезапуска службы и проверяет, что она остаётся активной после запуска.

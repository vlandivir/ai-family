# Решения

Первая фиксация — 22 сентября 2026. Дополнения — 23 сентября 2026.

## Принято

- Этот репозиторий публичный. Секретов в нём нет и не будет. Обсуждение архитектуры ведём здесь.
- Код приложения пишем позже, отдельным шагом. Секреты в git не кладём.
- Семейный сайт и воркер живут в этом репозитории.
- Семейный проект — отдельный репозиторий. Он может быть публичным или приватным.
- Проект описывает пайплайн: какие входные данные приходят, какие шаги их обрабатывают и как выглядит артефакт.
- Несколько проектов идут одновременно: их задачи лежат в одной очереди и чередуются. Примеры — квартира для аренды, автомобиль или зимняя резина, институт для сына, подготовка к регате.
- Данные, логин, файлы и очередь — Supabase, регион EU. Это обязательно в любой схеме.
- Доступ к строкам — RLS по членству в проекте. Админ назначает, кто какой проект видит.
- Вход в первую версию — Google через Supabase Auth. Первый админ — allowlist email владельца.
- Яндекс — позже, отдельным OIDC-провайдером.
- Один Next.js-сайт в этом репозитории. Отдельный деплой сайта на каждый проект не делаем.
- Бот тратит уже оплаченную подписку. Отдельный счёт OpenAI или Anthropic не заводим.
- Первый адаптер бота — Cursor SDK, local runtime, ключ `CURSOR_API_KEY`.
- Второй адаптер, когда понадобится — Claude Code CLI с токеном подписки. Флаг `--bare` не используем.
- ChatGPT Plus в первую версию не входит. Headless-клиент есть (`codex exec`), отдельным адаптером его пока не подключаем.
- Воркер — процесс Node.js на маленьком VPS в EU. Его держит systemd. Входящие порты не открываем: процесс сам опрашивает очередь.
- Один прогон бота за раз. Потолок задаёт подписка, не число ядер.
- Все задачи, включая отложенные, лежат в одной таблице `agent_jobs`. Отдельного поля приоритета нет.
- У задачи есть `not_before` — самое раннее время, когда её можно взять. Задача человека получает текущее время и стартует, как только закончится текущий короткий шаг. Следующие шаги пайплайна ждут со временем в будущем.
- Задачи делаем маленькими: одна ссылка, одна страница, один шаг.
- Ненужная задача отменяется статусом `cancelled` и больше не берётся.
- Время постановки, старта и финиша, вход, ошибка, контекст шага и ссылки на артефакты хранятся в строке задачи. Файлы — в Storage. После рестарта воркер поднимает строку, которая осталась в `running` дольше получаса.
- Сайт можно поставить на Vercel, на тот же VPS, что и воркер, или на статический хост. На очередь и адаптер это не влияет.
- Рабочая связка на старте: сайт на Vercel, воркер на VPS.

## Открыто

- Останется ли сайт на Vercel или переедет на VPS вместе с воркером.
- Когда переходить с Supabase Free на Pro. Повод — фото: на бесплатном плане Storage около 1 ГБ.

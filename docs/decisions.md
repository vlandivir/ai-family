# Решения

Первая фиксация — 22 сентября 2026. Ниже то, что уже работает, и идеи, работу над которыми отменили.

## Сделано

- Этот репозиторий публичный. Секретов в нём нет.
- Семейный проект — отдельный репозиторий, публичный или приватный, с префиксом `ai-family-`.
- Первый проект — квартиры в Белграде, приватный `ai-family-belgrade-apartments`. Правила отбора лежат там. Воркер подтягивает их `git pull` перед сообщением.
- Бот тратит подписку Cursor через CLI `agent` и ключ `CURSOR_API_KEY`. Отдельный счёт OpenAI или Anthropic не заводим. Имя модели каждого прогона пишется в задачу.
- Воркер — процесс Node.js на Hetzner. Его держит systemd. Пуш `ai-family` в `main` выкладывает его через GitHub Actions. Входящий порт машины — только SSH.
- Семья говорит с ботом в Telegram. В личке отвечает только allowlist. В группе отвечает в той же теме любому участнику.
- В одном контексте задачи идут по порядку, разные контексты обрабатываются параллельно (по умолчанию до трёх). Сообщение и ответ пишутся в `agent_jobs`.
- Очередь выбирает готовые задачи по `not_before`; при запуске и периодически возвращает прерванные задачи в очередь, не затрагивая активных агентов.
- Данные очереди, проектов и карточек — Supabase во Франкфурте. Фото карточек — Hetzner Object Storage.
- Витрина Белграда — отдельный Next.js в репозитории проекта, на Vercel. Без секретного пути страница каталога не открывается. По прямой просьбе в чате агент может поправить её код и отправить в `main`, сайт выложится сам.
- Новая карточка из темы получает одну из четырёх категорий каталога: под сдачу, для жизни, дом, новостройка. Повтор того же объекта обновляет существующую карточку.
- Два фоновых обработчика Белграда работают независимо от Telegram. Поисковый каждые 12 часов проходит все фильтры `scan.json` и найденные страницы пагинации, добавляя ссылки в общую очередь. Проверяющий последовательно обрабатывает старые и новые объявления с общим для поиска и проверки интервалом не менее минуты между обращениями к сайтам; к каждому объявлению возвращается не раньше чем через 24 часа, в том числе после ошибки. Новый объект разбирает в отдельном контексте Cursor, без предварительного повторного открытия; проверяет бюджет и сценарий поиска. По умолчанию за день по времени Белграда начинает не больше 100 новых разборов, проверка старых объектов этим лимитом не ограничена. Очередь не обрезается и сохраняется атомарно вместе с отметками проверок и ходом поиска. При изменении цены отправляет карточку с номером, адресом, статусом, ссылкой и старой/новой ценой; неотправленные сообщения сохраняет для повторной доставки. Ошибки HTTP и страницы без распознанных ссылок отмечает отдельно в журнале обхода.

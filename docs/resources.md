# Ресурсы

## Что нужно в любом случае

- Публичный репозиторий GitHub `vlandivir/ai-family`. Секретов в нём нет. Проекты — в отдельных репозиториях, публичных или приватных.
- Проект Supabase Free, регион EU. Для текста и небольших таблиц хватает. Фото упрутся в Storage (на free около 1 ГБ) — тогда Supabase Pro.
- Уже оплаченная подписка Cursor. Подписка Claude — когда появится второй адаптер.
- Google Cloud: OAuth-клиент для входа через Supabase. Бесплатно.
- Машина воркера. Это единственная часть, которую не закрывают ни Vercel, ни Supabase.

## Машина воркера

- Linux x64 или ARM64. Практичный выбор — Ubuntu 22.04 или 24.04.
- 2 vCPU, 4 ГБ RAM, диск от 20 ГБ. У Claude Code опубликованный минимум — 4 ГБ RAM. У Cursor SDK отдельной цифры нет; тот же запас покрывает Node-процесс и локальное хранилище прогонов.
- Исходящий HTTPS до Cursor или Anthropic и до Supabase. Входящие порты не нужны.
- Node.js 22.13+ для Cursor SDK.
- Для Claude Code — их нативный бинарник и токен `claude setup-token`.
- Секреты только здесь: `CURSOR_API_KEY` или `CLAUDE_CODE_OAUTH_TOKEN`, service role Supabase.

Фото и таблицы на воркере не хранятся.

## Куда поставить воркер

Маленький VPS в EU, порядка 2 vCPU и 4 ГБ (Hetzner CX22 или аналог). Процесс под systemd работает, пока включена эта машина. На схеме сайта и Supabase размер машины не сказывается. На этом же VPS позже можно отдать и сайт.

Облачный runtime Cursor постоянный воркер не заменяет. Там разовый агент в их виртуальной машине над клоном репозитория, а не процесс с нашей очередью.

## Хостинг сайта

Vercel воркеру не нужен. Он умеет отдать семье сайт.

- **Vercel Hobby.** Сайт живёт отдельно от воркера. Галерея и витрины открываются, даже когда машина с ботом спит. Свой домен не обязателен, хватит адреса `*.vercel.app`. Эту связку берём на старте, чтобы потрогать Vercel вместе с Supabase.
- **Тот же VPS, что и воркер.** Caddy отдаёт Next.js и сам получает сертификат. Отдельный аккаунт Vercel не нужен. Сайт падает вместе с этой машиной.
- **Статический хост** (Cloudflare Pages и аналоги). Если страницы только читают и пишут Supabase из браузера, серверный Node для сайта не нужен.
